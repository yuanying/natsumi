# 0028. iPhone のクライアント

- Date: 2026-09-22
- Status: Accepted（範囲外としていた裏にいる間の通知（APNs）は [ADR 0029](0029-push-notifications-on-the-iphone.md) で決定）

## Context

Mac アプリ（[ADR 0010](0010-mac-app-structure.md)）に加えて、iPhone からも natsumi と話したい。
画面は Claude Design の canvas で合意した（ログイン・メイン・履歴・話しかけたところ・設定の 5 画面と、メインのダーク）。
Mac の漫画の見た目（黒いインクの輪郭・白い吹き出し・黄色い知らせ・丸い日本語の書体）を引き継ぎ、
キャラクターのアニメーションはメインの画面だけで動かす。

`NatsumiCore` は AppKit に依存していない。import しているのは Foundation・CoreGraphics・Security・CryptoKit・ImageIO・
AuthenticationServices だけで、envelope・同期・会話の状態・ログイン・アバターの読み込み・何を既読にして何を見せるかの規則は、
そのまま iPhone でも使える。一方で、`UIMediator` と `UIState` は Mac の画面（舞台・ウインドウ・ポインタ・ショートカット）の
状態を多く持つ。

## Decision

### 1. 同じ Xcode プロジェクトに iPhone のアプリを足し、`NatsumiCore` を両方で使う

- `mac/Natsumi.xcodeproj` に、iPhone のアプリ `NatsumiPhone` を足す。`NatsumiCore` は macOS と iOS の両方で build する
  framework にする。ファイルは動かさず、Swift package にも切り出さない。移動の差分と、パッケージの版を管理する手間を増やさないためである。
- 対応するのは iOS 26 以降、iPhone だけ、縦向きだけとする。
- WebSocket の接続と GitHub ログインのアダプタは両方のアプリで同じなので、`mac/Shared/` に置き、両方のアプリのターゲットに入れる。
  違うのはログインのシートを出す先だけで、そこは `#if os(macOS)` で分ける。
- 署名は Mac と同じく指定しない。シミュレータではそのまま動く。実機に入れるときは、各自が自分のチームを選ぶ。
- ディレクトリの名前 `mac/` はそのまま残す。

### 2. iPhone は同じ構造で、自分の Event・State・Mediator・Props を持つ

[ADR 0015](0015-mac-ui-passive-view-tree.md) の構造（Root からなる木・Passive View・イベントのバブリング・
純粋な状態機械の Mediator）を iPhone でもそのまま使う。

- 木は `TreeComponent<Event>` として、イベントの型で汎用にする。Mac の `Component` と `EventSink` はその別名になり、
  iPhone は `PhoneComponent` と `PhoneEventSink` を使う。
- iPhone には、自分の `PhoneEvent`・`PhoneEffect`・`PhoneState`・`PhoneMediator`・`PhoneProps` を持たせ、`NatsumiCore/Phone/` に置く。
  Mac の `UIEvent` に iPhone の分を足さない。舞台・ウインドウ・ポインタ・ショートカットのない iPhone が、それらの状態を抱えないためである。
- 何を既読にするか、何を吹き出しに出すかは Mac と同じ規則を使う。`UIProps` の `shownReply`・`indicator`・`noticeStack`・`failures` を
  そのまま呼び、2 つのクライアントで、本人が見たものの扱いがずれないようにする（[ADR 0022](0022-only-her-last-line-in-the-balloon.md)、
  [ADR 0025](0025-her-reply-stays-while-she-keeps-thinking.md)）。
- Mediator と Props の導出は `NatsumiCoreTests`（macOS で動く）でテストする。

### 3. 画面は「ログインしているかどうか」で決まる

- セッションがなければログインの画面、あればメインの画面を出す。
- ログインの画面は、サーバーの URL と「GitHub でログイン」のボタンだけを持つ。サーバーがまだないときは「はじめまして」、
  前にログインしたサーバーがあるときは「おかえり」と迎え、その URL を欄に入れておく。
  URL の誤りとログインの失敗は、この画面に出す。Mac と違い、サーバーの設定とログインを 1 つの操作にする。
- セッションが切れたり失効したりすると、ログインの画面に戻る。

### 4. 裏に回ったら切り、前に戻ったら続きから同期する

iOS は裏に回ったアプリをすぐに止める。止まったまま接続を抱えていても、届いた出来事は受け取れない。

- 裏に回ったら、接続を切る（`SessionMachine` を止める）。
- 前に戻ったら、同じ `SessionMachine` のままつなぎ直す。stream の位置から同期し直すので、欠けた分だけが届き、
  送りかけのメッセージも残る。再接続の待ち時間の途中なら、待たずにつなぐ。
- 裏にいる間の通知（APNs）は、この ADR の範囲外とする（[ADR 0029](0029-push-notifications-on-the-iphone.md) で決定）。

### 5. メインの画面

- キャラクターは画面の下の中央に立ち、サーバーの表情に対応する spritesheet のアニメーションで動く。
- 吹き出しは画面の幅いっぱいに、最後の未読の返事を**全文**出す。Mac のように 5 行や 120 文字で切らない。
  長いときは吹き出しの中の本文だけがスクロールし、キャラクターと入力欄は動かない。
  場所が足りないとき（キーボードが出ているとき）は、キャラクターが高さの半分まで小さくなって本文に場所を譲る。
- 見出しに「なつみ · 時刻」を、右に × を置く。× は Mac と同じく、その返事までを既読にする。
  考え続けている間は、本文の下に考えている 1 行を添える（ADR 0025）。未読の返事がなく、受付中か考え中のときは、考えの吹き出しを出す。
  考えの吹き出しには × を置かない。
- 知らせは、吹き出しと同じ幅の黄色いカードに、先頭の知らせの 1 行目と「未読 N 件」を出し、後ろの枚数だけ縁を重ねる。
- 左上に接続の状態を出す。つながっていれば緑の点で「つながっています」、別の接続に切り替わったときなどは「接続し直す」を添えて押せるようにする。
- 下に入力欄と黄色い送るボタンを置く。送れなかったメッセージは入力欄の上に出し、× で消せる。
- ライトとダークの両方を持つ。吹き出しと知らせのカードは、ダークでも白と黄色のままにする（Mac と同じ）。

### 6. 話しかけている間は、彼女は顔になって場所を譲る

キーボードは画面の半分を占める。キャラクターが立ったままでは、彼女のセリフも、いま送った行も読めない。

- 入力欄に入ったかどうかは Mediator の状態にする（View が持つ焦点の状態ではない）。入力欄はそれを知らせ、返ってきた状態に従う。
- その間は、キャラクターの立ち絵をやめ、いまの気持ちの顔（丸いアイコン）にして入力欄のすぐ上に置く。
  顔は、横に出ている返事に込めた気持ち（[ADR 0026](0026-a-feeling-on-each-line.md)）で描く。返事が出ていないとき、
  気持ちの分からない返事のときは、立ち絵と同じくサーバーの表情で描く。
  彼女のセリフ（返事または考えの吹き出し）はその右に並べ、吹き出しの尻尾は顔の方（左）へ向ける。
- 知らせのカードは引っ込める。狭い場所では、彼女のセリフを隠してしまうためである。キーボードが下りれば戻る。
- 接続の状態の代わりに「閉じる」を出し、キーボードから出られるようにする。設定のボタンも引っ込める。
- 送ったばかりで、まだサーバーに記録されていないメッセージは、入力欄の上に「受付中…」を添えて出す。
  キーボードが下りている間は、送れなかったものだけを出す。

### 7. 履歴と設定は、メインの画面の上に重ねるページにする

- メインの画面の右上に、履歴と設定の丸いボタンを置く。知らせのカードを押しても履歴を開く。
  どちらもメインの画面の上に積むページで、戻るボタンか、端からのスワイプで戻る。どのページが開いているかは
  Mediator の状態であり、View の画面遷移はそれを映すだけにする。戻る操作もイベントとして Mediator に入れる。
- 履歴は Mac と同じ行（`UIProps.history`）を描く。natsumi のセリフには気持ちの顔を添え、いちばん新しいセリフだけ大きくする
  （[ADR 0027](0027-her-face-beside-each-line-in-the-history.md)）。知らせは黄色の吹き出しにし、下に入力欄を置く。
  開いたときと、行が届いたときと、キーボードの出入りで見える高さが変わったときは、いちばん新しい行を見せる。
- **履歴で見えた返事は既読にし、見えた知らせは確認済みにする。** 行の半分以上が画面に入ったら「見えた」とする。
  iPhone の知らせのカードには × がなく、カードは履歴への入り口なので、知らせは履歴で読んで確かめる形にする。
  履歴より前の知らせ（本文がなく、行がないもの）は、履歴を開いたときにまとめて確認済みにする。
- 設定には、サーバーの URL・接続の状態・この端末の ID・ログアウトを置く。GitHub のアカウント名、キャラクターと
  吹き出しの文字の大きさは、まだ置かない。

### 8. 偽のサーバーで画面を確かめる

GitHub もモデルも使わずに画面を確かめられるよう、`npm run fake-server` で動く偽のサーバーを `src/fake-server/` に置く。
loopback の http だけで待ち受け、`/auth/github/start` から GitHub を通さずに `natsumi://oauth/callback` へ返し、
誰にでもセッションを渡し、client-contract の会話の部分（snapshot・既読・知らせの確認・考えている 1 行と返事）を話す。
言うことはすべて架空で、メモリにしか持たない。

これを相手に、ログインからメッセージの返事までを辿って画面を撮る UI テスト（`NatsumiPhoneUITests`）を置く。
画面を見るための道具であり、偽のサーバーがないと通らないので、`NatsumiCoreTests` のような関門にはしない。

### 9. ロック画面からはアプリを開くだけにする

ロック画面からなつみを開けるよう、ウィジェットの拡張 `NatsumiWidgets` を足す。中身は 2 つで、どちらもアプリを開くだけである。

- ロック画面の下の隅（懐中電灯・カメラの場所）に置くボタン（ControlWidget）。同じものをコントロールセンターと
  アクションボタンにも置ける。押すとアプリの前の画面がそのまま出る。
- 時計の下に置く丸いウィジェット（accessoryCircular）。なつみの顔を出し、押すとアプリを開く。

会話（未読の返事や知らせ）はロック画面に出さない。ロックを外さずに見えてしまうことと、拡張から接続や
Keychain に触ると App Group が要り、無料の Apple ID では署名できないことによる。ボタンが実行する
`OpenNatsumiIntent` は、アプリと拡張の両方に入る `NatsumiLaunch/` に置く。

## Consequences

- iPhone と Mac は、接続・同期・既読・表示の規則を 1 つのコードで共有する。規則を変えると両方が変わる。
- `NatsumiCore` は iOS でも build されるので、AppKit に依存するコードを入れられない。
- iPhone では、知らせは履歴を開いて見ることで確かめる。Mac の × のように、読まずに確かめる方法はない。
- キーボードが出ている間、キャラクターは動かない。動くのは、キーボードが下りているメインの画面だけである。
- ロック画面のボタンとウィジェットは、アプリを開く以上のことをしない。ロック画面で返事を読みたくなったら、App Group と共有の保存先が要る。

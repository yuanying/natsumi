# 0023. どこからでも会話のウインドウを出すショートカット

- Date: 2026-09-21
- Status: Accepted

## Context

[ADR 0021](0021-the-input-and-the-history-in-one-window.md) の会話のウインドウを出すには、キャラクターをクリックするか、
右クリックのメニュー・メニューバーの「話しかける」を選ぶ。どれもマウスが要る。ほかのアプリで作業している手を
キーボードから離さずに話しかけたい、という要望が出た。キーは利用者が変えられること、既定は ⌘⇧N を第一の候補とし、
ほかとぶつかるならより良いものを提案すること、という指示だった。

## Decision

### 1. グローバルなショートカットで出す

1 つのキーの組み合わせを、**どのアプリが前面にあっても効く**ショートカットとして登録する。押すと会話のウインドウを
覚えている状態（畳んだ・開いた）で出し、前に出して key にし、入力欄に焦点を移す。すぐに書き始められる。

- **ウインドウが出ていても消さない。** キャラクターのクリックはトグルだが、ショートカットは「出して書ける状態にする」
  だけである。出ていて key でなければ、前に出して key にする。
- アプリは前面にしない。会話のウインドウは `.nonactivatingPanel` なので、アプリが前面でなくても key になり、
  文字を受け取る（ADR 0021）。前面のアプリへ戻るには、今までどおりそのアプリをクリックする。

### 2. 既定は ⌃⌥N

⌘⇧N は、Finder の「新規フォルダ」、Chrome・Edge・Brave・Arc のシークレットウインドウ、Safari のプライベート
ウインドウ、Xcode の「新規プロジェクト」と重なる。グローバルなショートカットは登録した組み合わせを**すべてのアプリから
奪う**ので、これらが使えなくなる。

既定は **⌃⌥N**（Control+Option+N）にする。macOS の標準にも、よく使われるアプリにも、Rectangle のような
ウインドウ管理のアプリにも、この組み合わせは見当たらない。N は natsumi の N である。利用者はこれを選んだ。

### 3. 設定で変える

設定に「ショートカット」の節を置く。ボタンに今の組み合わせ（⌃⌥N のように ⌃⌥⇧⌘ の順）を出し、押すと
「キーを押してください…」になって、次に押した組み合わせを新しいショートカットにする。

- **⌘・⌃・⌥ のどれかを含むものだけ**を受け付ける。修飾なしや Shift だけの組み合わせは、ふつうの文字入力を
  奪うためである。F1〜F20 は修飾なしでも受け付ける。受け付けなければ赤い字で理由を出し、記録を続ける。
- **Esc** で記録をやめる。もう一度ボタンを押す、設定を閉じる、設定が key でなくなる、のどれでもやめる。
  やめれば元の組み合わせのままである。
- 記録している間は今のショートカットの登録を外す。今と同じ組み合わせを押し直せるようにするためである。
- 「なし」でショートカットを無くし、「既定に戻す」で ⌃⌥N に戻す。
- 保存は `UserDefaults` の `hotKey`。保存が無ければ既定、「なし」も保存する。壊れた値は既定として読む。
- ほかのアプリが同じ組み合わせを先に登録していてシステムが受け付けなければ、設定にそう出す。

### 4. 作り

- 登録は Carbon の `RegisterEventHotKey` を使う。どのアプリが前面でもこのアプリに届き、**アクセシビリティの
  許可が要らない**。`NSEvent` のグローバルなモニタはキー入力に許可が要り、押したキーを横取りもできない。
- `HotKey`（キーコードと修飾キー、表示名、使えるかどうか）は `NatsumiCore` の値型で、テストする。
  キーコードで持つのは、システムに登録する値がそれだからである。表示名は ANSI の配列の名前で、JIS の配列でも
  英字と数字の位置は同じである。
- 押されたことは、ソケットと同じく外の世界の出来事として Root が `.hotKeyPressed` を Mediator に入れる。
  登録と保存は `UIEffect`（`.registerHotKey`・`.saveHotKey`）で、Root のアダプタ（`GlobalHotKey`）が行う。
  登録できなければ Root が `.hotKeyRegistrationFailed` を返す。
- 記録中のキーは、設定のコンポーネントが自分のウインドウのキー入力として受け（会話のウインドウが ⌘W を
  受けるのと同じ）、`.hotKeyRecorded` にして出す。記録中かどうかは Mediator の状態であり、View は持たない。

## Consequences

- マウスを使わずに、どのアプリからでも話しかけられる。
- 登録した組み合わせは、ほかのアプリのショートカットより優先される。設定の説明にそう書き、ぶつかれば利用者が
  変えるか「なし」にする。
- アクセシビリティの許可は要らないまま。
- 変更の範囲は Mac アプリだけである。サーバーとの契約は変わらない。

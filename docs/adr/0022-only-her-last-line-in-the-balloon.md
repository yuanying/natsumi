# 0022. セリフの吹き出しは最後の返事 1 件にする

- Date: 2026-09-21
- Status: Accepted

## Context

[ADR 0010](0010-mac-app-structure.md) の「未読の返事と知らせ」は、返事の吹き出しを**未読の返事の束**にした。
カーソルより後の返事を古い順に並べて一番古いものを前に出し、後ろの 2 枚を縁として重ね、残りを「あと N 件」と数える。
[ADR 0016](0016-opening-a-card-and-moving-the-character.md) は、× でその 1 件だけを既読にして次を前に出す形に改めた。

束にしたのは、最初の版で知らせが目に入らないまま返事に置き換わったためだった。その問題は、知らせを返事とは
別枠の束にしたことで解けている。返事まで束にすると、キャラクターが古いセリフから順に話すことになり、最後に何を
言ったかが前に出ない。未読をさかのぼって読むのは、[ADR 0021](0021-the-input-and-the-history-in-one-window.md) で
入力欄と一緒になった会話のウインドウのほうが向いている。

利用者は、**セリフの吹き出しは最新の 1 件だけにし、知らせは今までどおり重ねる**と決めた。
あわせて、何をしたら既読になるかも決め直した。今は、吹き出しの操作とキャラクターの右クリックのメニューでしか
既読にならず、ADR 0021 は会話のウインドウで開いても既読にしないとしている。

## Decision

### 1. 吹き出しには、未読の最後の返事を出す

- 返事の吹き出しに出すのは、**natsumi の最後の返事 1 件で、それが未読のときだけ**である。既読になれば出さない。
  知らせは返事ではないので、ここには出さない（知らせの束に出る）。
- 既読はカーソル 1 つなので、最後の返事が既読なら未読の返事は 1 件もない。したがって「未読があれば最後の返事を
  出し、無ければ出さない」と同じことである。
- **後ろに重ねる縁と「あと N 件」は、返事の側では廃止する。** 返事の吹き出しは常に 1 枚である。
- 本文の下の行の左端に**「未読 N 件」**を出す。N は `unreadReplyCount`（一覧の外の未読も数える）で、吹き出しが
  出ている間は常に 1 以上である。1 件のときも出す（件数で出し分けない）。場所・書体・色は、知らせの「あと N 件」と同じにする。
- 本文のクリックで全文に開くこと、切られている間の「続きは履歴で」（会話のウインドウを開いた状態で出す）は、
  ADR 0016・0021 のままである。
- 処理待ちの本人のイベントがある間は、返事の吹き出しを隠して考え中の吹き出しを出す（[ADR 0017](0017-streaming-the-line-she-is-thinking.md) のまま）。
  処理が終われば、その時点の最後の返事が未読なら戻る。
- 最後の返事は常に一覧（直近 500 件）の中にあるので、ADR 0010 の「一覧より古い未読は本文を出せず、吹き出しに
  出ない」場合は起きなくなる。

### 2. 既読になるできごと

返事が既読になるのは、次の 3 つだけである。どれも吹き出しを消す（既読になったから出さない、というだけで、
隠すための状態は持たない）。

1. **返事の吹き出しの ×。** 最後の返事まで `conversation.read` を送る。tooltip は「既読にして閉じる」とする。
2. キャラクターの右クリックのメニューの「返事をすべて既読にする」。× と同じ結果である。
3. **会話のウインドウで見たとき。** 次のすべてが揃ったら、**見えている最後の返事まで** `conversation.read` を送る。
   - 会話のウインドウが出ていて、履歴が開いた状態である。
   - その返事の行が、履歴のスクロール領域の中に見えている。
   - 会話のウインドウが key である（本人がそのウインドウを使っている）。

   条件は、ウインドウが key になったとき、履歴を開いたとき、スクロールしたとき、見えている範囲に返事が届いた
   ときに確かめ直す。カーソルが既にそこより先なら送らない。ADR 0021 §5 の「開いても既読にしない」はこれで置き換える。

**本人のメッセージの送信では既読にしない。** 契約のとおりである。畳んだ会話のウインドウ（入力欄だけ）で
話しているときは既読にならないので、返事は吹き出しに出る。

ほかの Mac で既読にしても、この Mac の吹き出しは消える。既読はサーバーのもので、すべての端末で共通である
（[ADR 0013](0013-read-state-on-the-server.md)）。

見えている行から送る位置を決める計算は `NatsumiCore` の純粋関数にし、UI なしでテストする。見えている行の
messageId は、ADR 0015 の木のとおり View からイベントとして Mediator に渡す。

### 3. 履歴を読んでいる間は、返事の吹き出しを出さない

会話のウインドウが出ていて、履歴が開いていて、そのウインドウが key の間（上の 2-3 の、行が見えていること
以外の条件）は、**未読の返事があっても返事の吹き出しを出さない。**

履歴を見ている最中に届いた返事は、描かれてから行が見えたと知らされて既読になる。この間だけ吹き出しが出て
すぐ消える、というちらつきを避けるためである。本人はそのウインドウで返事を読んでいるので、吹き出しは要らない。
ウインドウが key でなくなれば（ほかのアプリに移れば）、未読の返事は吹き出しに出る。

考え中の吹き出しは、この間も今までどおり出す。

### 4. 変えないもの

- **知らせの束**は ADR 0010・0016 のままである。未確認の知らせを重ね、「あと N 件」を出し、× で 1 件ずつ確認する。
- 楽観的な反映、`command.rejected` で戻すこと、切断中の送信を同期後に同じ requestId で送ることは ADR 0010 のままである。
- サーバーとの契約（`conversation.read`・`notification.ack`・snapshot）は変わらない。Mac は既読を保存しない。

## Consequences

- キャラクターは、まだ読んでいない最後の返事を出している。返事が続けて届いても、古いものから読み進める必要はない。
  間の返事は会話のウインドウで読む。
- × や右クリックのメニューで既読にすると、吹き出しに出なかった未読もまとめて既読になる。会話のウインドウでも、
  見えている範囲より前の未読は一緒に既読になる。カーソルが 1 つである以上、避けられない。
- 会話のウインドウで読んでいると、履歴の行の「未読」の印が見ている間に消えていく。
- 吹き出しに出ているかどうかは既読の状態だけで決まるので、Mac に隠した状態を保存しない。起動し直しても、
  未読の返事があれば出て、無ければ出ない。
- 返事の吹き出しが常に 1 枚になるので、配置の計算（`StackBudget`）で返事の後ろの枚数を減らす段が要らなくなる。
  知らせの束の段は残る。
- ADR 0010 の「返事の束」の節、ADR 0016 §1 の返事の側（× で 1 件だけ既読にして次を前に出す）、ADR 0021 §5 の
  「開いても既読にしない」を、この ADR で置き換える。
- 変更の範囲は Mac アプリだけである。

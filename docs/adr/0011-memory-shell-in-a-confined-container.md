# 0011. 閉じ込めたコンテナで、記憶を shell で探す

- Date: 2026-09-15
- Status: Accepted（記憶を読み取り専用にする点と、記憶の書き込みをサーバーのツールで行う点は [ADR 0018](0018-memory-in-git-and-the-nightly-rebuild.md) で置き換え、入れるコマンドの一覧・書ける場所・環境変数・資源の上限・答えの後までプロセスが動かないこと・作業ディレクトリ・ツールと設定とスクリプトの名前は [ADR 0019](0019-a-workspace-not-a-memory-tool.md) で置き換え）

## Context

ADR 0009 で、長期記憶は `memory/` の Markdown になり、モデルは `recall`・`read_memory` で探すようになった。
`recall` は文字の重なりで探すので、言い換え・正規表現・ファイルの一覧や件数では探せない。
`rg` のような CLI をモデルに使わせれば、この弱点の多くを補える。

一方、ADR 0004 は「任意 shell を許可しない」と決めている。閉じ込めのない shell をモデルに渡すと、次のことができてしまう。

- 秘密（GitHub の client secret、Pi の OAuth、設定）と SQLite を読む
- 外へ送る
- 記憶を壊す

後で Slack などの外部の入力が思考ループに入ると、プロンプトインジェクションの経路にもなる。
コマンド名の許可リストだけでは足りない。シェルの機能や `rg --pre`・`find -exec` のような引数で、許可していない処理を動かせる。

## Decision

### shell を、閉じ込めたコンテナの中だけで許す

モデルの shell は、natsumi とは別のコンテナ `natsumi-tools` で動かす。制限はコマンドの検査ではなく、コンテナの形で掛ける。
「中で何を実行されても、できることがこれだけ」という形にする。

- **入れるもの**: `sh` と、記憶を読むための `cat`・`find`・`grep`・`head`・`ls`・`rg`・`sort`・`tail`・`uniq`・`wc` だけにする。
  一覧は `docker/tools-commands.txt` に置き、ツールの説明とテストで同じ一覧を使う。
  - image は空の image（scratch）に、Debian のパッケージから、この一覧の実行ファイルと、それが読み込む共有ライブラリだけを写して作る。
  - ネットワークに出られる道具（`curl`・`wget`・`nc`）、パッケージマネージャー、インタプリタ（python・node など）、`git` は入れない。
  - ファイルを書き換えられる `sed`・`awk` や、`rm` も入れない。`awk` は `system()` で、GNU の `sed` は `e` コマンドで、別のコマンドを動かせる。
  - busybox は使わない。標準の image にはネットワークの applet（`nc`・`wget` など）が入っている。外すには自分でビルドした設定の維持が要る。
- **ネットワーク**: `network_mode: none`。インターフェースは loopback だけになる。
- **ファイル**: data directory の `memory/` だけを、volume の subpath で読み取り専用にマウントする。
  - data directory の他（SQLite・`personality.md`・ACME の鍵）はマウントしない。Pi の状態領域（session・auth）、`/run/secrets`、設定ファイルもマウントしない。
  - ルートファイルシステムは読み取り専用にする。書き込めるのは、16 MB の `/tmp`（noexec）だけとする。
- **権限**: 非 root で動かし、全 capability を外し、`no-new-privileges` を付ける。
  - UID は natsumi と同じにする。記憶のファイルは所有者だけが読める（0600）ためである。
  - 別コンテナで、マウントも別なので、同じ UID でも natsumi のプロセスやファイルには届かない。
- **環境変数**: コンテナには何も渡さない。コマンドには `PATH` と作業ディレクトリの `PWD` だけを渡す。
- **資源の上限**: CPU 1、メモリ 256 MB（swap なし）、プロセス数 64 とする。
  - 1 回のコマンドは 10 秒で、プロセスグループごと止める。
  - 標準出力と標準エラー出力は、それぞれ 64 KiB まで残す。
  - natsumi の側でも、モデルに返す文を切り詰める。

### natsumi からの呼び出し方

- natsumi に Docker のソケットを渡さない。`docker exec` も使わない。Docker のソケットを持つことは、ホストの root を持つことと同じである。
- `natsumi-tools` の中で、実行役（runner）を常駐させる。natsumi とは、両方のコンテナがマウントする小さな tmpfs の volume に置いた Unix ソケットだけでつながる。
- runner は Go で書き、静的にリンクした 1 つのバイナリにする。インタプリタも libc も要らず、依存は標準ライブラリだけである。
  image のビルドの中で、runner のテストを実行する。
- 手順は次のとおりとする。
  1. natsumi が、コマンドの文字列を 1 行の JSON で送る（16 KiB まで）。
  2. runner は、`memory/` を作業ディレクトリにして、`sh -c` で実行する。コマンドは新しいプロセスグループで動く。
  3. 時間の上限か、シェルの終了で、グループに残ったプロセスを止める。バックグラウンドに残したプロセスが、答えの後まで動くことはない。
  4. runner は、終了コード（シグナルで止まったときはシグナル名）、標準出力、標準エラー出力、切り詰めと時間切れの印を、1 行の JSON で返す。
- runner は、コマンドを 1 つずつ実行する。natsumi の側も、ツールの呼び出しを 1 つずつ送る。Pi は、1 回のモデル呼び出しに含まれるツールを並行して実行するためである。
- runner は、ソケットを作った後、ソケットの置き場のディレクトリを読み取り専用（0555）にする。
  コマンドも runner と同じ UID で動くが、`chmod` がないので、ソケットを消したり置き換えたりできない。
  runner の起動時に、ディレクトリを書き込み可能に戻して、古いソケットを置き換える。
- runner のバイナリは `PATH` の外（`/usr/libexec`）に置く。パスを指定すれば実行できるが、`sh` でできる以上のことはできない。
- コンテナは `init: true` で動かす。runner が止めたコマンドの孫プロセスを、init が回収する。
  このため Docker が差し込む `/sbin/docker-init`（tini）も実行できるが、子を起動して見守るだけで、`sh` にない機能は増えない。
- runner に届かない、応答がない（20 秒）、応答を読めない場合は、ツールの結果にその理由を書いて返す。思考ループは止めない。
- ヘルスチェックは、runner に何もしないコマンドを送って、終了コード 0 が返るかで判定する。
- `natsumi-tools` は natsumi の起動（healthy）を待つ。natsumi が初回の起動で `memory/` を作り、subpath のマウントにはそのディレクトリが要るためである。

### Pi のツール

- 設定の `loop.memoryShellSocket` に runner のソケットのパスがあるときだけ、`run_memory_shell(command)` を登録する。system prompt にも、そのときだけ使い方を 1 行足す。
  - 設定がなければ、今までどおり shell はない。開発の環境で Docker なしに動かすときも、この形になる。
- ツールの説明には、次を書く。
  - 使えるコマンドの一覧
  - 記憶が読み取り専用であること
  - ネットワークがないこと
  - 記憶の変更は `remember`・`forget` で行うこと
  - 時間と出力に上限があること
- 送る前に、空のコマンド、2000 文字を超えるコマンド、NUL 文字を含むコマンドを拒否する。
- ツールの結果は、状態が分かる文にする（ADR 0008）。
  - 終了コードを書く。1 のときは「rg と grep は、見つからないときも 1 を返す」と添える。
  - 標準出力は 8000 文字、標準エラー出力は 2000 文字まで返す。runner か natsumi で切り詰めたときは、そう伝え、`head`・`rg -m`・`wc -l` で絞れると書く。
  - 時間切れとシグナルでの停止は、エラーの結果にして、途中までの出力を付ける。
- `recall`・`read_memory`・`remember`・`forget` は残す。記憶の書き込みは、今までどおりサーバーのツールだけで行う。

### 置き換える既存の決定

- ADR 0004
  - 置き換え:「任意 shell、任意 HTTP、任意 credential 読み出しを許可しない」のうち、shell の部分。
    この ADR の閉じ込めたコンテナの中に限り、モデルに任意の shell のコマンドを許す。
    natsumi のコンテナの中での shell と、任意の HTTP、credential の読み出しは、引き続き許さない。
  - 具体化:「実行プロセスは専用の非 root コンテナ/OS ユーザーで動かし、必要な volume だけを mount する」「ネットワークの到達先制限とファイル権限はデプロイ側で実施し、SDK allowlist と別に試験する」。
    shell については、この ADR のコンテナの形と、`scripts/check-memory-shell-sandbox.sh` の実測で行う。
- ADR 0009
  - 追加: 記憶のツールに `run_memory_shell` を足す（runner の設定があるときだけ）。「任意のファイルの読み書きと shell は、引き続き許さない」は、この ADR の範囲で置き換わる。

## Consequences

- モデルは記憶を shell で読める。その結果は思考の context に入る。
  - 記憶の中身が外へ出る道は、モデルが返事や投稿に書くことだけになる。shell の側から外へ送る手段はない。
  - 残るリスクは、モデル経由の持ち出しである。本人以外に届く出力（Slack への投稿など）は、本人の承認で止める前提とする（grill-me Q5）。
    この前提が崩れると、プロンプトインジェクションで記憶が漏れ得る。
- コマンドは、読み取り専用の記憶、`/tmp`、`/proc` の自分のコンテナの範囲を読める。
  上限の中で CPU とメモリを使い、runner を止めることもできる（止まるとコンテナが再起動する）。これは本人の思考ループを遅らせるだけで、natsumi 本体には及ばない。
- `natsumi-tools` の UID は、natsumi の UID と合わせる必要がある。natsumi の UID を override で変えたら、`NATSUMI_TOOLS_UID` も同じにする。
- コンテナとイメージが 1 つずつ増える。runner のビルドには Go の image を使う。
- image の中身は Debian のパッケージのバージョンに従う。`rg` などのバージョンを上げるときは、image を作り直す。
  一覧にないコマンドが入っていないこと、閉じ込めが効いていることは、`scripts/check-memory-shell-sandbox.sh` で確かめる。
- Wiki の書き込みや git を shell から行うことは、この ADR の範囲外である。書き込みを許すなら、別の閉じ込めと承認を決め直す。

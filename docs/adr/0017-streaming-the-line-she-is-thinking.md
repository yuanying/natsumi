# 0017. 考えている 1 行を流し、考え中を吹き出しにする

- Date: 2026-09-18
- Status: Accepted

## Context

[ADR 0008](0008-single-thinking-loop-and-mac-conversation.md) は「返事は『考え中』の表情のあと全文を表示する」と決め、
Pi の session は思考の記録として別に持ち、Mac には出さないとした。`docs/client-contract.md` もそれを受けて
「Pi の session ID・entry ID・思考・ツールの呼び出しはクライアントに渡さない」「途中の文字列は流れない」と書いている。

その結果、いまの Mac の「考え中」は、処理待ちの本人のイベントがある間だけ出る吹き出しで、中身は点滅する
「・・・ 考え中」だけである。返事が出るまで、natsumi が何をしているのかは分からない。

[ADR 0010](0010-mac-app-structure.md) はさらに、**未読の返事があるときは「考え中」「受付中」を出さず**、
未読の返事を出したまま、本文の下の小さな回る印で処理中であることを示す、と決めていた。

利用者から次の要望が出た（原文の要点）。

- 考え中の吹き出しに、**thinking をストリーミングで出したい。**
- **全文である必要はなく、吹き出しの大きさを変える必要もない。1 行ずつ切り替わっていく感じ。**
- メッセージは**灰色**にして thinking だと分かるようにしたい。
- 吹き出しを、セリフの吹き出しではなく**漫画の「考え中」（雲の吹き出し）**にしたい。
- **thinking 中は、返事の吹き出しが出ていても考え中の吹き出しに切り替えてほしい。**

つまり、思考を Mac に出さないという ADR 0008 の決定と、未読の返事を優先するという ADR 0010 の決定の、
どちらも一部を覆すことになる。覆す範囲と、覆さない範囲を決める必要がある。

決めることは次のとおりである。

1. 何を流すか（全文か 1 行か）、どれくらいの頻度で、どこまでの長さで流すか。
2. 記録するか。`session.snapshot` や履歴に入れるか。
3. stream の採番（`seq`）とどう折り合いを付けるか。再接続の再送を悪くせず、この event を知らない
   クライアントを壊さないこと。
4. どのターンで流すか。
5. 思考の本文に混ざり得るもの（記憶の shell が返したファイルパスなど、[ADR 0011](0011-memory-shell-in-a-confined-container.md)）を
   どう扱うか。
6. Mac 側の見え方。形・色・大きさ・行の切り替え・× の意味・「受付中」の扱い。

## Decision

### 1. 流すのは「いま書かれている 1 行」だけで、記録しない

新しい全端末向け event `conversation.thinking` を足す。payload は `line` の 1 つだけで、
**natsumi がいま書いている行**（思考の本文の、最後の改行より後ろ）を運ぶ。

- **全文は流さない。** 改行が来たら、その行は過去のものになり、新しい行に入れ替わる。Mac は積み上げない。
- **SQLite に記録しない。`session.snapshot` にも履歴にも入れない。** 処理が終われば消える。
  「Mac に見せる会話の正本は SQLite」という ADR 0008 の決定は変えない。**思考は会話ではない。**
  Pi の session が思考の記録であることも変えない。流すのは、その記録の一部を横から見せているだけである。
- **返事の途中の文字列は、今までどおり流さない。** 返事は確定した全文が 1 度だけ届く。覆すのは思考の扱いだけである。

### 2. 粒度・間引き・上限

- **行が育つ途中も流す。** 文字が増えていく様子が見えるほうが、書いている感じが出る。
- **間引く。** 同じ行が変わり続けても、**250 ms に 1 回まで**しか送らない。その間に書かれた分は、
  次に送るときの行に含まれている。
- **思考のかたまりが終わったとき（`thinking_end`）は、間引きに関わらず最後の行を送る。**
  そうしないと、最後に書かれた行が出ないまま終わることがある。
- **空行は送らない。** 改行の直後は行が空になるが、それを送ると点滅に戻ってしまう。
  次の行に中身が入るまで、前の行が出たままになる。
- **1 行は 120 文字まで。** 超えた行は**新しいほうの端を残す**（先頭を落として `…` を付ける）。
  書いているのは行の末尾なので、そこが見えているほうが正しい。
  契約の 1 メッセージ 64 KiB の上限からは十分に遠いが、量の上限は契約に書く。
- **ターンが終わったら `line` が空の `conversation.thinking` を 1 度送る。** これが「思考は終わった」の合図で、
  Mac は `conversation.event.completed` の扱いに関わらず点滅に戻れる。

### 3. 採番しない。stream の今の番号のまま送る

`conversation.thinking` は**その場限りの event** とし、**stream の `seq` を消費せず、再送のバッファにも入れない。**
envelope には、**その stream がいま出している `seq`（最後に採番した番号）をそのまま付けて**送る。

理由:

- **ふつうに採番してバッファに入れると、再接続の再送が今より悪くなる。** バッファは stream ごとに既定 256 件しかない。
  長い思考が 250 ms ごとに 1 件を積めば、1 分で会話の event を押し出してしまう。再接続のたびに snapshot に
  落ちるのは、この機能のために払う代償として大きすぎる。契約の「再送を悪くしない」を満たせない。
- **`seq` を持たない envelope という新しい種類を作ると、この event を知らない古いクライアントが壊れる。**
  いまの Mac は `seq` の無い envelope を malformed として扱う。契約の「未知の type は無視する」が効かなくなる。
- **今の番号のまま送れば、両方を満たせる。** この event を知らないクライアントは「すでに受け取った `seq`」として
  黙って捨てる（`StreamTracker` の重複の扱い）。知っているクライアントは、**位置を動かさずに**適用する。
  番号を消費しないので、次の会話の event は今までどおり `seq + 1` で届き、抜けにはならない。
- 受け取れなかった端末に後から届ける意味も無い。**いま書いている行は、いま見えることにだけ意味がある。**

Mac 側は `StreamTracker` に 1 つ規則を足す。思考の行は、**同じ epoch・同じ stream のときだけ適用し、位置は動かさない。**
同期の前（位置がまだ無い）や別の stream のものは、再同期を求めずに捨てる。出す先の吹き出しがまだ無いからである。

### 4. 流すのは、本人が待っているターンだけ

- **本人のメッセージを処理しているターンだけ流す。** ターンの途中で差し込まれた（steer された）メッセージも
  含む。Mac は処理待ちの本人のイベントがある間しか吹き出しを出さないので、それ以外で流しても見えない。
- **夜の振り返り（rotation）では流さない。** 「振り返りそのものは会話に出ない」という契約を変えない。
- **合図（ping）や自発的な確認（self-check）のターンでも流さない。** 本人は何も待っていない。
- **設定 `pi.thinking` が `off` のときは流さない。** モデルが思考を返さないときも、流れるものが無いので
  今までどおり点滅の「考え中」のままである。

### 5. モデル呼び出しの境目では、最後の行を残す

ツールを呼んで、また考える、というターンでは、呼び出しの境目で**最後の行をそのまま残す**。
消して点滅に戻すと、ツールを実行している間ずっと「止まった」ように見える。実際には動いているので、
最後に考えていたことを出したままにする。新しい思考が始まれば、その行に入れ替わる。

### 6. 中身の安全

思考の本文には、記憶の shell が返したファイルパスなど（ADR 0011）が混ざり得る。

- **これは本人だけが見るものである。** 届くのは [ADR 0006](0006-github-login-and-transport.md) の認証を通った、
  本人の GitHub アカウントの端末だけで、記憶も shell の結果も、もともと本人のものである。
  本人の記憶の中のパスが本人の画面に出ることは、漏洩ではない。
- **それでも、サーバー自身の内部は渡さない。** 契約の「内部のファイルパス、認証情報、Pi の session ファイル参照、
  任意の Pi SDK 呼び出しをクライアントに転送しない」はそのまま残す。流すのは、natsumi が書いた思考の本文だけである。
- **ツールの呼び出しの引数も結果も流さない。** 思考の本文（`thinking` のブロック）だけを読む。
  契約の「ツールの呼び出しはクライアントに渡さない」は、この形で残る。
- **記録しないことが、ここでも効いている。** 一度きり流れて消えるので、後から読み返される場所には残らない。

### 7. Mac: 漫画の考え中の吹き出し

- **形は「考え中」の吹き出し（thought bubble）にする。** セリフのしっぽの代わりに、キャラクターへ向かって
  小さくなる丸が 2 つ並び、輪郭は雲のように膨らむ。輪郭の太さ・紙の色・書体は返事と同じ漫画の作法にそろえる。
  **返事のセリフの吹き出しの形は変えない。** 別の形を足し、どちらを描くかは描画パラメータで渡す。
- **文字は灰色**にして、返事（黒）と見分けが付くようにする。
- **大きさは変えない。** 1 行ぶんの高さ・いまの列の幅で固定する。入りきらない行は末尾を切る（省略記号）。
  **行が変わっても、吹き出しも舞台も大きさを変えない。**
- **行の切り替えは 0.2 秒のクロスフェード。** 前の行が消えながら次の行が出る。積まない。スクロールしない。
- **行がまだ無い間は、今までどおり「・・・ 考え中」の点滅。** 行が届いたら行に置き換わる。
  行が出ている間は、形と色が「考え中」を語っているので、小さなラベルは出さない（tooltip には残す）。
- **配置の計算を、行の切り替えで走らせない。** 吹き出しの高さは行の中身によらず 1 行ぶんなので、
  一列の配置は何も変わらない。行だけが変わったときは、前の配置をそのまま使って描き直す。

### 8. Mac: 処理中は、未読の返事より考え中を前に出す

**これは ADR 0010 の「未読の返事があるときは『考え中』『受付中』を出さず、小さな回る印で処理中を示す」を覆す。**

- 処理待ちの本人のイベントがある間は、**未読の返事の束を隠して、考え中の吹き出しを出す。**
  処理が終わったら、返事の束（その間に届いた新しい返事を含む）に戻る。
- **小さな回る印（`isBusy`）は取り除く。** 考え中の吹き出しが出ているときに未読の返事は出ないので、
  「未読の返事の横で処理中を示す」場面がもう無い。
- **「受付中」も同じ形にする。** サーバーが受け付ける前と受け付けた後は、本人にとっては同じ一続きの出来事である。
  形が切り替わったり、その拍子に返事の束が出たり消えたりしないほうが落ち着く。違うのはラベルだけにする。
- **知らせの束は今までどおり**、一列の中の別のパネルとして出たままにする。隠すのは返事の束だけである。

### 9. × の意味は「この 1 回の処理の間、隠す」

今の × は「中身が変わるまで隠す」だったが、行が流れると中身は常に変わる。

**1 回の処理（処理待ちのイベントが空になるまで）を 1 つの中身として扱い、その間は隠したままにする。**
行が切り替わっても、受付中から考え中に変わっても、その間に返事が届いても、出し直さない。
処理待ちのイベントが無くなったところで隠しは解け、未読の返事があれば返事の吹き出しが出る。

### 10. 決めなかったこと

- **履歴（`HistoryView`）は変えない。** 思考は履歴に残らないので、出すものが無い。
- **`pi.thinking` の既定は変えない。**
- **何行ぶんを見せるか（2 行以上）は作らない。** 1 行で足りるという利用者の指示に従う。
- **行を本人の側で止める・遡る手段は作らない。** 記録が無いので、遡る先が無い。
- **ADR 0008 と ADR 0010 は書き換えない。** この ADR が改める部分は、それぞれの Status の行から辿れる。

## Consequences

- 返事を待っている間、natsumi が何を考えているかが見えるようになる。返事が遅いときに、止まっているのか
  考えているのかが分かる。
- **思考が本人の画面に出る以上、モデルが書いた思考は「誰にも届かない内心」ではなくなった。**
  ADR 0008 の前提のうち、この 1 点だけが変わる。ただし記録はされず、本人以外には届かない。
- サーバーは Pi の session を購読して思考の delta を読む。ターンの実行そのもの（`session.prompt` を await する形）は
  変えていない。
- `seq` を消費しない event という形は、契約に新しい種類を 1 つ増やした。将来これを増やすときは、
  **再送されないこと・古いクライアントが重複として捨てること**が両方成り立つ event にだけ使う。
- 未読の返事が処理中に隠れるので、**「返事が来たのに一瞬で消えた」ように見える場面が出る**（返事が届いてから
  `finish_event` までの間）。返事は消えたのではなく待っているだけで、処理が終われば必ず出る。履歴にも残っている。
- 回る印を取り除いたぶん、Mac の描画パラメータは 1 つ減った。
- 思考の行が途中で切られる（120 文字）ため、長い 1 行は末尾しか見えない。全文は Pi の session の記録にある。

# 0032. 本人と話すのは reply_to_mac で、回数も相手のメッセージも問わない

- Date: 2026-09-23
- Status: Accepted

## Context

[ADR 0008](0008-single-thinking-loop-and-mac-conversation.md) と [ADR 0024](0024-no-event-ids-for-the-model.md) で、
`reply_to_mac` は「まだ返事をしていない本人のメッセージへの返事」に限られていた。

- このターンで見た、まだ返事をしていない本人のメッセージが無ければ断る。断る文は「付け足しは `notify_owner` で」と案内する。
- 返事を 1 回送ると、それらのメッセージは返事済みになる。同じターンの 2 回目は断られる。
- SQLite では、返事の行は必ず答えたイベントを持ち（CHECK）、1 イベントに返事は 1 つ（一意インデックス）だった。

このため、合図（ping）や予約した確認（self_check）のターンで natsumi が本人に話しかけるには、`notify_owner` しか無かった。
知らせは本人が 1 件ずつ確かめるまで残るもので（[ADR 0013](0013-read-state-on-the-server.md)）、
「そろそろお昼ですね」のような会話のセリフには重い。返事の後に一言付け足すときも同じである。
しかも知らせには件数の上限があり、会話の続きがそれを消費していた。

利用者は、`reply_to_mac` の「1 ターン 1 回」と「本人のメッセージが要る」制限をなくすと決めた。

## Decision

### 1. 役割を分ける

- **`reply_to_mac` は会話のセリフである。** 本人のメッセージへの返事にも、自分から話しかけるのにも使う。
- **`notify_owner` は、本人に確かめてほしい相談や知らせである。** 本人が確かめるまで残る。
  既読とは別の確認（`unacknowledged_notices`）と、件数の上限（1 ターン 3 件、直近 1 時間で 12 件）は変えない。

### 2. `reply_to_mac` は何回でも、本人のメッセージが無くても送れる

- 1 ターンに何回でも呼べる。本人のメッセージが無いターン（`ping`・`self_check`）でも呼べる。
- 件数の上限は設けない。歯止めは、1 ターンのモデル呼び出しの上限だけである。
- 夜の振り返り（`nightly_review`）の間だけは断る。`notify_owner` と同じ扱いで、断る文には
  「明日に伝えたいことは `write_handoff_note` に」と書く。
- 本文の検査（ADR 0008）はこれまでどおり行う。
- 成功の結果の文は「続けて話してもよいが、同じことを繰り返さない。ほかにやることがなければ、ツールを呼ばずに終える」とする。

### 3. 最初の返事が、待っているメッセージに答える

- このターンでなつみが既に見ていて、まだ返事をしていない本人のメッセージがあれば、次の `reply_to_mac` が
  そのすべてへの返事になる（ADR 0024 §2 のまま）。
  - 返事の行は、答えたメッセージのうち **いちばん新しいもの** のイベントに結びつける。
  - 答えたメッセージは、返事を送ったのと同じトランザクションで返事済み（`replied`）にする。
    再起動をまたいで二重に返事扱いしない性質は、これで保つ。
- 待っているメッセージが無いときのセリフ（2 回目以降、合図のターン、steering で入ったメッセージを見る前）は、
  **どのイベントにも結びつけない。** 何にも答えていないからである。

### 4. 記録と配信

- SQLite の schema を 11 にする。`conversation_messages` から「返事はイベントを持つ」CHECK を外す。
  - SQLite は CHECK を外すのに表を作り直すしかない。ほかの列、制約、行はそのまま移す。
  - 1 つのイベントに答える返事は最大 1 つ、という一意インデックスは残す。イベントを持たない返事は、
    このインデックスに掛からない（NULL どうしは重ならない）。
  - この表は `loop_events`・`read_cursor`・`notice_acknowledgements` から参照されている。作り直しは
    SQLite の手順どおり外部キーを切って行い、コミットの前に参照が切れていないことを確かめる。
    切れていれば migration ごと戻す。migration の仕組みに、外部キーを切って流す指定を足す。
- クライアント契約（`docs/client-contract.md`）は最小限に変える。
  - `conversation.message` の kind: reply の `replyTo` は、本人のメッセージに答えたときだけ付く。
    答えていないセリフには欄が無い（null ではなく省く。ADR 0026 と同じ形）。
  - 「1 つのメッセージへの返事は最大 1 回」は「1 つのメッセージに答える返事は最大 1 回」と読み替え、
    その後に続けて話すセリフも kind: reply で届くことを書き足す。
  - Mac と iPhone の `NatsumiCore` は、`replyTo` を任意の欄として読んでおり、それを前提にした表示の分岐も無い。
    アプリの変更は要らない。
- ほかの振る舞いは変えない。
  - 未読の返事の数は kind: reply をすべて数える。自分から話しかけたセリフも未読になる。
  - iPhone への通知も、kind: reply ならすべて送る。固定の本文「返事があります」は変えない。
    通知の拡張が復号した本文に置き換えるので、本人の目に入るのはセリフそのものである。
  - `conversation.event.completed` は、これまでどおり本人のメッセージのイベントにだけ送る。
    合図のターンで話しかけても、合図は返事済みにならない。
  - `session.snapshot` の `pendingEvents` は、答えたメッセージが外れる点も含めて変わらない。

### 5. system prompt とツールの説明

- 使い分けが読めるように書き換える。「本人と話す（返事も、自分から話しかけるのも）: `reply_to_mac`」
  「本人に確かめてほしい相談・知らせ: `notify_owner`（本人が確かめるまで残る）」。
- `ping` の説明に、話しかけるなら `reply_to_mac`、確かめてほしい知らせなら `notify_owner` と書き足す。
- 説明は固定の文のままにする（[ADR 0019](0019-a-workspace-not-a-memory-tool.md)）。

## 置き換える既存の決定

- **ADR 0008**
  - 置き換え: ツールの表の `reply_to_mac` の「対象はこのターンで処理中の本人のメッセージに限る。1 イベント 1 回」。
    対象のメッセージが無くても送れ、回数も限らない。1 つのイベントに答える返事が最大 1 つで、
    再起動をまたいでも SQLite の一意制約で守ることは残す。
  - 置き換え: 同じ表の `notify_owner` の「返事とは別の、本人への相談・知らせ」。本人に確かめてほしい相談・知らせとし、
    会話のセリフは `reply_to_mac` で送る。件数の上限は変えない。
  - 置き換え: ツールの結果の例「返事は確定し、このメッセージにはもう送れない」。
  - 置き換え: 本文の検査の「拒否しても、1 イベント 1 回の枠は消費しない」。枠そのものが無くなる。
    拒否したセリフは何にも答えず、書き直したセリフが待っているメッセージに答える。
  - 残す: 単一の思考ループ、本文の検査、Mac に見せる会話の記録と配信、再起動のときの扱い。
- **ADR 0024**
  - 置き換え: §2 の「無ければ断る。断る文には、送れない理由と、代わりにどうするか（付け足しは `notify_owner`、
    なければそのまま終える）を書く」と「返事を送った後に steering で新しい本人のメッセージが入れば、もう 1 回送れる」。
    待っているメッセージが無くても送れる（夜の振り返りの間を除く）。
  - 置き換え: §2「記録と配信」の「クライアント契約と SQLite の schema は変えない」。schema 11 と、
    `replyTo` を任意にする契約の変更がこの ADR で入る。
  - 置き換え: Consequences の「同じターンに差し込まれた複数のメッセージに、別々の返事を返すことはできない。
    まとめて 1 回で答える」。答えるのはまとめて 1 回のままだが、その後に続けて話すことはできる。
  - 残す: モデルにイベントの ID を扱わせないこと。答えるのは見たメッセージだけで、いちばん新しいものに結びつけること。
    答えたメッセージを同じトランザクションで返事済みにすること。
- **ADR 0014**
  - 補足:「声をかけるかは natsumi が決める」の声をかける手段に、`reply_to_mac` が加わる。合図と予約の形は変えない。
- **ADR 0013・0026・0029** は置き換えない。自分から話しかけたセリフも kind: reply であり、
  既読のカーソル（0013）、セリフの気持ち（0026）、iPhone への通知（0029）は返事と同じに扱う。

## Consequences

- 合図や予約のターンで、会話のセリフを知らせではなく返事の吹き出しで話しかけられる。知らせは、
  確かめてほしいものだけに残る。
- 返事の後の一言の付け足しに、知らせの上限を使わなくなる。
- `reply_to_mac` には件数の上限が無いので、同じことを何度も話しかける振る舞いを止めるのはモデル自身と、
  1 ターンのモデル呼び出しの上限だけである。結果の文と説明で「同じことを繰り返さない」と伝えている。
  実際に多すぎる場面が出たら、上限を足すかを改めて決める。
- 話しかけたセリフはすべて未読として数えられ、iPhone に通知される。合図のたびに話しかけると、それだけ通知が増える。
- 履歴の上では、答えていないセリフも返事と同じ白い吹き出しで並ぶ。どのメッセージに答えたかは `replyTo` で分かるが、
  いまのアプリはそれで表示を変えない。
- system prompt とツールの説明が変わるので、走っている session の prefix cache は一度失われる（ADR 0019）。
- schema 11 は `conversation_messages` を作り直す。更新後の最初の起動で一度だけ、会話の行数に比例した時間がかかる。

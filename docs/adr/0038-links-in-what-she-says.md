# 0038. 本文の中の URL をリンクにし、クリックでブラウザを開く

- Date: 2026-09-25
- Status: Accepted

## Context

natsumi の返事や知らせ、本人のメッセージには URL が入ることがある。Mac と iPhone のアプリは本文を素の文字として描いており、
URL はクリックもタップもできなかった。開くには、文字を選んでコピーし、ブラウザに貼るしかなかった。

- GUI は Passive View の木で作る（[ADR 0015](0015-mac-ui-passive-view-tree.md)、`mac/CLAUDE.md`）。View は Props を描くだけで、
  利用者の操作はイベントとして mediator が裁定し、外の世界への作用は効果として Root が行う。
- 返事の吹き出しと知らせのカードは、本文全体のクリックが「全文を出す／畳む」になっている（[ADR 0016](0016-opening-a-card-and-moving-the-character.md)、
  [ADR 0022](0022-only-her-last-line-in-the-balloon.md)）。本文全体が 1 つのボタンだった。
- 履歴の本文は文字を選べる（`textSelection`）。
- サーバーとの契約（[client-contract](../client-contract.md)）は本文を素の文字で送る。Markdown の記法は約束していない。

## Decision

### どこをリンクにするか

- 本文の中の、スキームから書かれた `http://` と `https://` の URL だけをリンクにする。スキームは大文字でもよい。
  `file:`・`javascript:`・`mailto:`・`ftp:` などのほかのスキームと、スキームの無い `example.com` や `www.` で始まるものはリンクにしない。
- 見つけ方は `NSDataDetector` ではなく、`NatsumiCore` に置く自前の走査にする。
  - `NSDataDetector` はスキームの無いドメインやほかのスキームもリンクにする。日本語の文の中で URL がどこで終わるかも、こちらで決められない。
  - URL は ASCII の文字だけでできているとみなす。日本語の文字や全角の記号（「。」「、」「）」「」」「…」など）に当たったところで終わる。
    空白と、RFC 3986 が URL に許さない文字（`<>"{}|\^` とバッククォート）でも終わる。
  - 終わりにある半角の `.,;:!?'*` は、文の終わりの記号として URL に含めない。閉じ括弧 `)]}` は、URL の中に対になる開き括弧が無ければ含めない
    （`https://example.com/wiki/Foo_(bar)` の `)` は URL の一部）。
  - 英数字の直後から始まるもの（`xhttps://…`）と、ホストの無いもの（`https://`、`https:///path`）はリンクにしない。日本語の直後から始まるものはリンクにする。
- Markdown の `[文字](URL)` は解釈しない。契約が素の文字である以上、記法を読むのはこの決定の範囲外である。
- 吹き出しと知らせのカードは、畳んでいる間は本文の頭だけを「…」で切って出す。切れ目まで続く URL は途中までしか無いので、リンクにしない。
  開いて全文を出すと、その URL もリンクになる。

### リンクを Props に入れる

- 本文を「文字の並び」と「リンク（書かれたままの文字と URL）」の列に分ける処理は、I/O の無い純粋関数として `NatsumiCore` に置く。
- 本文を持つ Props（履歴の行・送りかけの行・返事の吹き出し・知らせの束・iPhone の吹き出し）は、本文と並べてこの列を持つ。
  View はその列を、リンクに下線を付けた 1 つの文として描くだけで、URL を探さない。

### 開く動作はイベント → mediator → 効果にする

- リンクのクリック（Mac）とタップ（iPhone）は、SwiftUI の `openURL` の既定の動作に任せず、そのリンクが描かれたコンポーネントから
  イベント（リンクを開きたい）として出す。mediator はそれを「既定のブラウザで開く」効果として返し、Root が実行する
  （Mac は `NSWorkspace`、iPhone は `UIApplication`）。
  - 規約どおり、動作を決めるのは mediator である。`openURL` に任せると、開くかどうかの判断が View の環境に埋もれ、テストもできない。
  - mediator は、`http` と `https` のほかのリンクを開かない。View には最初からほかのリンクを渡していないが、入口で 2 度目の確かめをする。
- **リンクを開いても、何も既読にしない。** 吹き出しも知らせもそのまま残り、サーバーには何も送らない。
  - 既読にするのは × と、会話のウインドウで行が見えたことだけである（[ADR 0022](0022-only-her-last-line-in-the-balloon.md)）。リンクを開くことは本文を読み終えたことを意味しない。
  - ブラウザから戻ったときに、吹き出しの残りを読んで閉じられる。

### 吹き出しと知らせのカードの本文はボタンにしない

- ボタンは、その中の文字のリンクのクリックも自分のものにしてしまう。本文をボタンで包むのをやめ、文字にクリックの動作を付ける。
- リンクの上のクリックはリンクを開き、それ以外の場所のクリックは今までどおり「全文を出す／畳む」になる。本文にリンクの無いときの振る舞いは変わらない。
- 履歴の本文は、文字の選択とリンクのクリックの両方ができる。

### Mac ではリンクのある本文を `NSTextView` で描く

- Mac の履歴・返事の吹き出し・知らせの束の本文は、SwiftUI の `Text` ではなく、読み取り専用の `NSTextView`（`NSViewRepresentable`）で描く。
  リンクの上での指の形、リンクのクリック、文字の選択は、`NSTextView` の標準の動きに任せる。カーソルを自前で扱うコードは書かない。
  - SwiftUI の `Text` では、リンクの上で指の形にならなかった。`pointerStyle` とリンクの位置を自前で控える方法も試したが、指の形にならなかった。
    文字を選べる本文では、選択の I ビームのほうが勝った。
- リンクのクリックは `NSTextViewDelegate` で受け、自分では開かず、リンクを開きたいというイベントとして出す。開くかどうかは mediator が決める（上の節のまま）。
- 履歴の本文は文字を選べる。吹き出しと知らせのカードの本文は選べない。リンクの外のクリックは、そのカードのクリック（全文を出す／畳む）になる。
  カードの本文は幅いっぱいを取るので、短い行の横のクリックも今までどおりカードのものになる。
- 高さは、表示に使う `NSTextView` とは別の組版で測る。行数の制限は、`NSTextContainer` の最大行数と末尾の省略で表す。
  SwiftUI が決めた幅で測った高さを返すので、吹き出しとカードの計測と開閉は今までどおり SwiftUI の配置に乗る。
- iPhone は SwiftUI の `Text` のまま描く。

### 対象にしない表示

- 考えている 1 行（`ThinkingLine`）。1 行に切り詰めて、書いている端だけを見せる表示であり、URL が途中で切れる。
- iPhone のメイン画面の知らせのカード。本文の 1 行目だけを 1 行に切り詰めて出し、カード全体のタップが履歴を開く。
  知らせの本文のリンクは、開いた履歴から開ける。
- 送れなかったメッセージの知らせ（「〜を送れませんでした」）。本人が書いた文を引いているだけで、読む場所ではない。

## Consequences

- 返事・知らせ・本人のメッセージの URL を、Mac ではクリック、iPhone ではタップで既定のブラウザに開ける。
- URL の見つけ方・終わりの扱い・切った本文の扱い・Props に入ること・mediator が開く効果を出すこと・既読にしないことは、
  `NatsumiCoreTests` で UI なしにテストする。
- リンクのクリックと本文のクリックの振り分け、履歴で文字の選択とリンクが両立すること、リンクの上でポインタが指の形になることは
  `NSTextView` に頼っており、自動テストが無い。実機で確かめる。
- Mac の本文は `NSTextView` で組むので、`Text` で描いていた頃とは行の高さや折り返しが少し変わることがある。
- ASCII でない文字を含む URL（国際化ドメイン名や、パスに日本語をそのまま書いたもの）は、ASCII でない文字の手前までしかリンクにならない。
  natsumi の返事で必要になったら、見つけ方を見直す。
- 本文の表示は Props の導出のたびに URL を走査する。走査は本文の長さに比例する軽い処理で、履歴の全行に対して行う。

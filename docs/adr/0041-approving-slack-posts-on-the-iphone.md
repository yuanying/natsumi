# 0041. Slack の投稿を iPhone で承認する

- Date: 2026-09-26
- Status: Accepted

## Context

natsumi が Slack に出したい投稿のうち、ポッポさんが本人に回したもの・判定できなかったもの・同じ返信先で 3 回目に突き返されたものは、
本人の承認を待つ（[ADR 0040](0040-the-dove-sends-what-jev-passes.md)）。承認の画面は iPhone に置くと決めていた（Mac は後で）。
サーバーとの形は [クライアント契約](../client-contract.md) の「Slack の投稿の承認」と「iPhone への通知」にある。

承認は、送る本文・返信先・置き場所の全体に結び付く（[ADR 0002](0002-client-events-and-approvals.md)）。本人が見たものと違うものを
送ってはならず、同じ決定を二度送ってもならない。iPhone のアプリは裏に回ると接続を切り（[ADR 0028](0028-the-iphone-client.md)）、
承認待ちは通知で知る（[ADR 0029](0029-push-notifications-on-the-iphone.md)）。

## Decision

### 1. 承認待ちは接続の状態として持ち、画面はその Props から描く

- `session.snapshot` の `pendingApprovals`、`approval.pending`・`approval.resolved` を、会話と同じ stream の出来事として
  `SessionMachine` が受け、承認待ちの一覧（`ApprovalBook`）を持つ。snapshot で置き換え、pending で足し、resolved で閉じる。
- 読めない承認（知らない `kind`、形の壊れたもの）は、その 1 件だけを落とす。1 件のために snapshot 全体を捨てない。
  知らない表情・判定・置き場所の値は「無い」と読む。
- 画面は既存の規約（`mac/CLAUDE.md`）どおり、`PhoneMediator` の状態から `NatsumiCore` の純粋関数で Props を作る。
  View が持つ状態は、修正中の本文（入力欄の下書きと同じ理由）だけである。

### 2. 画面は「会話の画面の件数 → 一覧 → 1 件」

- 会話の画面の状態の下に「承認待ち N 件」を出し、押すと一覧を開く。1 件もなければ出さない。書いている間も出さない。
- 一覧は古い順に、チャンネル・下書きの 1 行目・回った理由（短く）・作った時刻を出す。
- 1 件の画面は、返信先（チャンネル、返す相手の発言者・時刻・書き出し）、置き場所、下書きの全文と表情の顔、回った理由、
  問題点ごとの点数（しきい値を超えたものは赤く、印を付ける）、前の突き返しの下書き、作った時刻と期限を出す。
- 操作は「却下」「修正」「承認して送る」の 3 つを画面の下に置く。修正を選ぶと下書きが入力欄になり、「修正して送る」で送る。
- 置き場所は、返す相手の発言があるときだけ「スレッド／チャンネル」を選べる。チャンネルそのものへの投稿には選ぶものが無い
  （サーバーも無視する）。承認でも修正でも、選んだ置き場所が元と違うときだけ `placement` を付ける。
- 閉じたら、何が起きたか（承認して送った・修正して送った・送れなかったとその理由・却下・期限切れ）と、実際に送った本文を上に出す。
  選んだ置き場所は閉じた後もそのまま出す。

### 3. 決定は 1 件に 1 つだけ、見た revision で送る

- 決定は、本人が見ている承認待ちの `revision` で `approval.decide` にする。
- 送っている間と、受け付けられて結果を待っている間は、同じ承認に次の決定を作らない。二重に押しても 1 回だけ送る。
- 同期の前に選んだものと、`sync-required` で断られたものは、同期してから同じ requestId で送り直す。
  サーバーは閉じた承認への決定に閉じたときの状態を返すので、送り直しても二重にはならない。
  同期したときにもう承認待ちでなければ（別の端末で閉じた、期限が切れた）、その決定は捨てる。
- `stale-revision`・`invalid-request` で断られたら理由を出し、もう一度選べるようにする。新しい revision が届いたら、前の決定は消す。

### 4. 通知は復号してチャンネルと下書きの先頭を出し、タップでその承認を開く

- kind: approval の alert は、Notification Service Extension が approvalId を AAD にして `e` を開き、
  副題に「承認待ち · チャンネル」、本文に下書きの先頭を出す。開けなければ「承認待ちがあります」のままにする。
- 通知をタップすると、どの画面にいてもその承認を開く。戻ると一覧に出る。
- kind: approval-resolved の background では、その承認の通知を消し、バッジを直す。
- 同期したときのバッジは、未読の返事と未確認の知らせと承認待ちの数の和にし、承認待ちでなくなったものの通知を消す。

## Consequences

- 本人は、通知から 1 回のタップで承認の画面に着き、送る本文・返信先・置き場所を見てから決められる。
- 電波の悪いところで押しても、つながり直したときに送られる。別の端末で先に閉じていれば送られない。
- 承認の履歴を見る画面は無い。閉じた承認は、この起動の間に見ていたものだけ結果を出せる。
- Mac の承認画面は、同じ `ApprovalBook` と Props の上に後で作る。

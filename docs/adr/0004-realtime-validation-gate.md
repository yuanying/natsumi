# 0004. 音声は実接続による検証を導入条件にする

- Date: 2026-09-14
- Status: Accepted

## Context

Codex App Server の型に realtime メソッドが存在しても、独自 Linux サーバーでの
Plus 認証による音声利用や Mac の音声入出力を保証するものではない。

## Decision

実験的メソッドは `experimentalApi: true` で初期化する隔離ハーネスから検証する。
既存の認証は読み取り専用のファイル参照とし、認証のコピー・更新・ログ出力は行わない。
専用の一時 Codex home と架空会話を使用し、API key 方式や Plus 以外の account はモデル呼び出し前に拒否する。
有料 API への自動切り替えはしない。

`thread/realtime/started` と開始 RPC 成功は要求の受理として扱う。
実際の音声出力イベントを受信するまで音声動作成功と判定しない。
入力音声の受理、サーバー音声出力、実音声の認識、Mac の録音・再生・割り込みは別々に評価する。
検証失敗時は `realtimeEnabled: false` を維持し、テキスト機能の開発を進める。

実行コマンド、CLI バージョン、結果と未検証範囲は [probe-results.md](../probe-results.md) に記録する。
実験的型はバージョン更新時に再生成して確認する。通常テストは外部接続を行わない。

## Consequences

初期音声機能の提供可否は、実測で条件を満たすまで未確定となる。
API 利用条件・上限・実験的仕様の安定性について、単一アカウントでの試験結果を一般化しない。
Mac およびコンテナの試験はそれぞれ対応環境の後続作業で行う。

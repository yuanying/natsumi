# 0040. ポッポさんは Jev が通したものを送り、本人には回されたものだけを承認してもらう

- Date: 2026-09-26
- Status: Accepted

## Context

[ADR 0012](0012-slack-and-colleagues.md) と [ADR 0039](0039-slack-as-files-and-a-scored-dove.md) で、Slack への出力の骨組みを決めた。
natsumi は Slack に投稿するツールを持たず、送信役の同僚「ポッポさん」への依頼（`ask_agent`）だけで投稿する。
ポッポさんは Jev（TypeSafe AI）の問題点ごとの点数で判定し、本文のある投稿は、判定が「送る」でも最初はすべて本人の承認を待つ。

ADR 0039 の受け取り側の実装が済み、送信側を作る前に、次の点が決まっていなかった。

- 返事のアイコン（ADR 0039 で「表情に合わせて変える」と決めた）をどこに置き、Slack にどう渡すか。
- Jev は英語が最も正確で、日本語は「扱えるが同じようには良くない」と案内されている。問いと材料の言語をどうするか。
- 判定なしの投稿をどう扱うか。
- 本人の承認画面をいつ作るか。承認の API と通知の形を、iPhone の側とどう合わせるか。

本人は、承認の既定について考えを改めた。今の natsumi は、漏れて困る秘密を持っていない。
本人は「どのくらいまで喋るか、Jev がどのように拒否するかを徐々に観察したい」と考え、
Jev の判定で承認が必要になった投稿だけを承認することにした。

また、本人は TypeSafe のアカウントを作れなかった。当面は、Jev と同じ API（同じ要求と応答の形）を返す OSS を自前で動かして使う。
その互換サーバーは、問いの種類の一部しか実装していないことがあり、応答の欄が欠けることもある。

## Decision

### 本文のある投稿は、Jev の判定が「送る」なら自動で送る

- 当面、本文のある投稿の既定を「すべて本人の承認」にしない。Jev の判定が「送る」なら、本人の承認なしに送る。
- 本人の承認を待つのは、次の 3 つだけとする。
  - Jev の判定が「本人に回す」になった投稿
  - 判定なしの投稿（Jev が使えない、答えが崩れた。ADR 0012 のまま）
  - 同じ返信先で 3 回目の突き返しになった投稿（書き直しは 2 回まで。ADR 0012 のまま）
- 送る直前の機械的な検査、判定と本人の判断の一致の記録、同意の証拠はサーバーの承認記録だけ、という点は変えない。
- 観察のために、送った本文、Jev の点数、置き場所、本人の判断を SQLite に記録する。個人データとしてバックアップの対象にする。

### ポッポさんはサーバーの中にいる

- ポッポさんは `ask_agent` の相手の名前 `poppo` で呼ぶ。A2A の相手ではなく、サーバーの中で処理する。ツールは増やさない。
- Slack の設定があるときだけ、頼める相手の一覧（`/manual/agents/INDEX.md`）に載せる。頼み方はマニュアルの Slack のページに書く。
- `poppo` は外のエージェントの名前に使えない（設定で断る）。
- `ask_agent` の結果は、受け付けたことだけを返す。結果は後から、外のエージェントの返事と同じ `agent_reply` の出来事で、
  `agent: poppo` と、何が起きたか（届けた・リアクションを付けた・本人に回した・突き返した・本人が見送った・期限切れ・届けられなかった）を付けて返す。
  台詞はサーバーが整え、モデルに口調を書かせない。出来事には Slack の ts も承認の ID も載せない（ADR 0024）。

### 依頼の形と、返信先の突き合わせ

- 依頼は ADR 0039 の見出し付きテキスト（`返信先`・`種類`・`表情`、`---` の後が本文）とする。
  形が崩れている、見出しが足りない・知らない・重なる、表情が一覧に無い、というときは、頼まずにその場で直し方を返す。
- 返信先の参照は、サーバーの記録（Slack の発言の表）と、ワークスペース・チャンネル・本人のタイムゾーンの日付と秒までの時刻・発言者で突き合わせる。
  - 見つからなければ、その場で断る。
  - 同じ秒に同じ発言者の発言が複数あれば、候補の書き出しを添えて断る。natsumi は参照の最後に書き出しを「」で添えて指定し直せる。
- 本文は、頼まれたときにも送る直前と同じ機械的な検査に掛け、当たればその場で断る。

### 判定

- 判定のモデルは Jev とする（ADR 0039）。問いは英語で書き、下書きと周りの発言は日本語のまま渡す。
- Jev に見せるのは、チャンネルの名前、返す相手の発言、その周りの発言（スレッドなら直近、チャンネルなら前の数件。件数と文字数は設定）、下書きだけとする。
  natsumi の説明や記憶は見せない（ADR 0012）。
- 1 回の呼び出しで、問題点ごとの Noul と、置き場所（スレッドかチャンネルか）の Choice を聞く。チャンネルそのものへの投稿では置き場所を聞かない。
- 問題点は、ループの評価で出た失敗に合わせて 6 つとする。スレッドに無い情報、本人に代わる約束・期限、隠しごとの匂わせ、事実と違う説明、同意の捏造、私的な事情。
- 判定はサーバーの決まりで点数から出す。しきい値は設定で持つ。
  - 「本人に回す」のしきい値以上の問題点に印を付ける。
  - 印の付いた問題点のどれかが「突き返す」のしきい値以上なら、突き返す（はっきりした問題は natsumi が直す）。
  - 印の付いた問題点がすべてそれ未満なら、本人に回す（はっきりしない問題は本人が見る）。
  - 印の付いた問題点が無ければ、送る。
  - 初期値は、本人に回す 0.3、突き返す 0.7 とする。事前の評価（下記）の結果を見て設定で直す。
- Jev の失敗、429・529 を含む 4xx・5xx、時間切れ、答えの欄の欠け（問題点の点数、置き場所の選択）は、判定なしとする。
  置き場所の確率は承認画面に見せるためだけのものなので、欠けていても判定なしにはしない。
- 判定なしのときの置き場所は ADR 0039 の決まりによる。返す相手の発言がチャンネル直下で、その後の発言が設定の件数以内ならチャンネル、ほかはスレッド。

### Jev と互換のサーバー

- Jev のクライアントの接続先（base URL、既定は TypeSafe のもの）と model の名前を設定で変えられるようにする。
- API キーは省ける。省いたら `Authorization` を付けない。キーを付けて平文の http で送るのは、同じ機械の中の相手に限る。
- 下書きと周りの発言は、設定した接続先に出る。出口の許可リストに、その接続先を加える必要がある（ADR 0034）。

### 送る

- `chat.postMessage` で投稿する。スレッドに返すときは、返す相手の発言のスレッド（返信ならその親）に入れる。リンクは展開しない。
- 送る直前に、機械的な検査（ADR 0008 と同じ）を掛ける。本人が修正した本文にも掛ける。当たれば送らない。
- 返す相手の発言が消されていれば送らない。
- 送る途中でサーバーが止まった投稿は、再起動の後も送り直さない。届いたか分からないものを二重に送るよりは、届けられなかったと知らせる。
  判定の途中で止まった投稿は、再起動の後に判定し直す。

### 返事のアイコン

- 表情ごとのアイコンを、なつみのサーバーが認証の要らない道 `/avatar/<表情>.png` で配る。Slack にはその URL を `icon_url` で渡す。
  URL は設定の `publicOrigin` から作る。表情は ADR 0026 の一覧で、依頼に表情が無ければ neutral とする。
- PNG は Mac のアイコン（WebP）から一度だけ変換してリポジトリに置く。Node は WebP を読めず、ビルドのたびに変換するためだけに依存を増やしたくないからである。
  アイコンは natsumi のキャラクターの公開のアセット（CC BY 4.0）であり、ほかのものはこの道から取れない。
- Slack の App には `chat:write.customize` の scope が要る。

### リアクション

- 絵文字は設定の候補の一覧に限る。候補に無いものは、その場で断り、候補を示す。Jev の判定も本人の承認も通さない（ADR 0039 のまま）。

### 本人の承認

- 承認は iPhone で行う（ADR 0039）。サーバーと iPhone の契約は `docs/client-contract.md` の「承認と外部実行」「iPhone への通知」に書く。要点は次のとおり。
  - 承認は ID と revision を持ち、作った時点の中身（返信先・置き場所・下書き・表情・判定の理由・前に突き返された下書き）で固定する。本人が承認するのは、見せられた中身である。
  - `session.snapshot` に承認待ちの一覧を載せ、承認待ちができたときと閉じたときに全端末へ知らせる。
  - 本人は承認・修正・却下を選べる。承認と修正では置き場所を変えられる。修正した本文は Jev に掛け直さない。
  - 決定は SQLite の条件付き更新で 1 回だけ受け付ける。閉じた承認への重複の回答には、閉じたときの状態を返す（ADR 0002）。revision が違えば断る。
  - 期限は既定 7 日（設定）。過ぎたら閉じ、natsumi に知らせる。期限を過ぎてから届いた決定では送らない。
  - 接続していない iPhone には、承認待ちができたときに alert を、閉じたときに background の push を送る。下書きの先頭とチャンネルは端末の鍵で暗号化する（ADR 0029）。
    バッジの数に承認待ちの件数を足す。
- Mac の承認画面は後で足す。

### 事前の評価

- ループの評価で出た失敗の場面（匂わせ・嘘・約束・捏造した同意・私的な事情・スレッドに無い情報）と、正しい投稿の例を、架空の文で用意する。
- それを Jev（または互換サーバー）に判定させ、しきい値ごとに、止めた数と正しい投稿を止めた数を出すスクリプトを置く。
  しきい値は、その結果と運用での本人の判断との一致の記録を見て決める。

### 置き換える既存の決定

- ADR 0012
  - 置き換え:「本文のある投稿は、最初はポッポさんの判定が『送る』でも、本人の承認を待つ」「広げる前の既定は『すべて本人の承認』」。
    判定が「送る」なら自動で送り、本人に回すもの・判定なし・3 回目の突き返しだけを承認に回す。
  - 残す: 判定なしは自動で送らない。書き直しは同じ返信先で 2 回まで。承認は送る本文と返信先の全体に結び付ける。送る直前の機械的な検査。
- ADR 0039
  - 置き換え:「ADR 0012 のまま進めるもの」のうち「本文のある投稿は、判定が『送る』でも最初はすべて本人の承認を待つ」。
  - 決定:「アイコンの画像の置き場所と、Slack に渡す方法の細部」。サーバーが `/avatar/<表情>.png` で配り、`icon_url` で渡す。
  - 具体化:「判定のモデルは Jev」。接続先と model の名前は設定で変えられ、Jev と同じ API の互換サーバーも使える。
- ADR 0002
  - 具体化: 承認の対象に Slack の投稿を加える。承認の重複・競合・期限切れの扱いは同じとする。

## Consequences

- 本人が見る前に、Jev が通した投稿は Slack に出る。Jev が見逃した漏えいや匂わせは、そのまま相手に届く。
  参加させるのが漏れてよいチャンネルだけであり、natsumi がまだ困る秘密を持っていない、という今の前提で受け入れる。前提が崩れたら、この決定を見直す。
- 判定の質は、しきい値と、互換サーバーのモデルの日本語の力に左右される。事前の評価と、運用での一致の記録を見て、しきい値を直す必要がある。
- 判定の問題点は、事前に並べた 6 つからしか出ない（ADR 0039 のまま）。
- 判定なしが増えるほど、承認が増える。互換サーバーが止まれば、すべての投稿が本人に回る。
- 承認は iPhone でしかできない。iPhone が手元に無ければ、回された投稿は期限切れになる。
- 送った本文、判定の点数、本人の判断が SQLite に残る。個人データとしてバックアップの対象になる。
- アイコンの URL は `publicOrigin` から作るので、Slack がそのホストに届かなければ、投稿のアイコンが既定の bot のものになる。
- 送る途中で止まった投稿は、届いていても「届けられなかった」と知らされることがある。
- 同じ秒に同じ人の発言が複数ある返信先には、書き出しを添えないと返せない。
